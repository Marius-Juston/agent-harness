# Pre-registration: researcher effort and a Sonnet 5.5 search helper against Opus 5.5 at high (#262)

Frozen 2026-11-19, before any trial. Changes after the first trial are dated amendments at the end, never edits.

## 1. Question and arms
Does the researcher keep its audited-claim accuracy at lower cost when (B) Opus 5.5 runs at effort `medium`, or (C)
Opus 5.5 at `medium` hands searching and source reading to a Sonnet 5.5 helper, against (A) Opus 5.5 at `high`, the
current frontmatter (`plugins/harness-ops/agents/researcher.md`)?

| arm | main thread | effort | helper |
|---|---|---|---|
| A | `harness-ops:researcher`, `--model opus` | high | none (Agent is disallowed, as shipped) |
| B | `harness-ops:researcher`, `--model opus` | medium | none |
| C | `researcher-helper` (the shipped researcher prompt plus one delegation paragraph, Agent allowed only for `research-scout`), `--model opus` | medium | `research-scout`, `model: sonnet`, read-only tools (Bash for `uv run dev lit`, WebSearch, WebFetch, arxiv MCP reads), returns at most about 1,500 words of extracts with verbatim quotes, titles, authors, years and links; it writes no files |

Arm C's two agent definitions are generated by `scripts/arm_c_agents.py` from the shipped researcher prompt at the trial
commit and passed with `--agents`. Effort is passed as `--effort` and `CLAUDE_CODE_EFFORT_LEVEL`, as `dev eval` does,
so in arm C the helper also runs at `medium`.

## 2. Tasks
`questions.yaml`: ten primary past round-1 sub-questions (Q01-Q10) and two spares (Q11, Q12). A spare replaces a
primary only when the primary cannot run for a reason recorded before any of its outputs is scored. Gold is the round
file the original researcher wrote, from a note whose research-auditor fixes are committed.

Trial workspace: a `git clone --local` of the trial commit with no remote; the question's `hide` paths, the
`common_hide` paths and the INDEX.md rows linking a hidden note are deleted and the deletion committed in the clone.
Prompt: the `template` with the question's `prompt`. The gold files were written 2026-10-12..20, after the June 2026
training cutoff of the model running this experiment, so recall from training is not expected (BELIEVED).
Leakage check: a trial whose transcript reads or fetches a hidden path or its GitHub URL is flagged and scored apart.

## 3. Runs
`claude -p --output-format stream-json --verbose --no-session-persistence --permission-mode acceptEdits`, the
`dev eval` default allowlist plus WebSearch, WebFetch and the arxiv MCP read tools, `--max-turns 150`, a 45-minute
timeout and a per-run `--max-budget-usd` cap fixed per stage (§6). Billing is the owner's API key, passed on the
command line only. Arms of one question run back to back in the order A, B, C rotated by question number, so time
of day and API load spread over arms.

## 4. Metrics
Per trial, from the stream-json transcript and the written file:
- **Audited-claim accuracy (primary).** A research-auditor run (Opus 5.5, `high`, its shipped frontmatter, the same
  for every arm) audits the trial's file renamed to `answer.md` with arm, effort and model stripped, sampling the
  10 claims that carry the file's main findings (all if fewer). Accuracy = (supports + 0.5 x partly supports) /
  claims sampled; "does not support" and "unsourced" count 0.
- **cite-check problems:** `uv run dev cite-check <file>` dead links plus title mismatches.
- **Gold-source recall:** the share of the gold file's distinct cited works (DOI, arXiv id, else URL without
  scheme and trailing slash) that the trial file also cites. Secondary; it rewards finding what the original found.
- **Cost:** `total_cost_usd` of the result event, and tokens by kind (input, cache write 1 h, cache write 5 min,
  cache read, output) also priced at `[tool.devkit.prices]` so cache writes are priced apart; per model for arm C.
  Turns and wall time.
- **Accepted:** accuracy at least 0.80 and 0 cite-check problems. **$ per accepted note** = the arm's researcher $
  over its accepted trials (auditor $ is the measurement's cost and is reported apart).

## 5. Decision rule
Per arm: mean accuracy over questions (trials averaged within a question first). Let `best` be the highest arm mean.
An arm is eligible when its mean is at most 5 points below `best`. Among eligible arms the one with the lowest
$ per accepted note wins; when two are within 10 % of each other the one with fewer parts wins (B, then A, then C).
The recommended researcher setting is the winner. Also reported, not deciding: for each arm against A, the question
bootstrap one-sided 95 % lower bound of the accuracy difference (10,000 draws, seed 262), as `dev eval --compare`
computes it. With 10 questions, 3 trials and 10 claims the point rule picks an equal arm 84-95 % of the time and a
10-point-worse arm 4-14 % of the time, while the bound shows non-inferiority at 5 points only 39-58 % of the time
when arms are equal (VERIFIED simulation under ASSUMED accuracy 0.75-0.85, `scripts/power_and_cost.py`). So the
point rule decides, and a winner whose bound is below -0.10 ships with a 30-run follow-up on live research issues.

## 6. Stages and budget
- **Stage 0, pilot (allowed now, owner budget $15 for this issue).** Question Q06 (picked by
  `random.Random(262).choice` over Q01-Q10), one trial per arm, cap $3.80 per run, total cap $13 including
  overshoot of the last turn. No auditor run (no budget for it), so **no accuracy and no verdict**: it measures cost,
  tokens, turns, whether arm C delegates, cite-check problems and gold-source recall, and whether the workspace,
  hiding and tools work headless with an API key. Stop before any run whose cap would take the ledger past $13.
- **Stage 1, full (needs an owner-approved budget).** Q01-Q10, three trials per arm, 90 researcher runs and 90
  audits: $339-535 at repo-E's per-run costs (VERIFIED arithmetic, `scripts/power_and_cost.py`), $226-357 for arms A
  and B alone. Per-run cap: twice stage 0's highest run cost in that arm.
