# r1-outside: outside evidence on drift in long-running, agent-run projects (#282, round 1)

Search coverage: `uv run dev lit status` on 2026-10-19 showed openalex (key), s2 (key), crossref, europepmc and arxiv all up ("discovery: OK"). Also used: the arXiv MCP (abstracts, single-section text search), WebFetch of three Anthropic posts and two doc pages, WebSearch (one lookup), the GitHub API via `gh` (300 repositories, 240 context-file histories, trees) and PyPI. One full text refused (ACM PDF for Xia et al., HTTP 403), so that paper is abstract-only. Not repeated here: everything [decision-records-and-drift.md](../../decision-records-and-drift.md) §3 and §6 already cite (Tan/Wagner/Treude, READU, dos Santos, Chakrabarti, Khatri, Wang skills, Su, lychee, Sadowski).

Labels: VERIFIED = measured here (script named; scripts live in this run's scratchpad, listed at the end, for the synthesis to copy), SOURCED = cited and fetched, BELIEVED = judgment. Every LLM result names its models; none is comparable to today's Claude models without re-measurement.

## Findings

### F1. Context files change often, mostly by addition, and agents now write much of the documentation work
- VERIFIED ([summarize.py](#scripts)): of the 300 most-starred GitHub repositories pushed since 2026-10-01, 164 have a root CLAUDE.md or AGENTS.md (76 have both). Taking each repository's most-revised file (>5 lines) that is at least 183 days old: n = 106 (77 AGENTS.md, 29 CLAUDE.md), median age 280 days. Median 17.5 commits (quartiles 5 / 17.5 / 51, max 635), **2.0 commits per month** (quartiles 0.49 / 2.01 / 4.49). Median length grew 109 -> 158 lines (growth ratio 1.4; quartiles 1.0 / 1.4 / 2.2); 75 grew, 23 shrank, 8 unchanged. Median last edit 11 days ago; 23 of 106 untouched for 90+ days. Median 4 distinct authors. Caveat: the commits API does not follow renames, and these are popular repositories, not agent-run ones.
- SOURCED: 2,303 context files from 1,925 repositories "evolve like configuration code through frequent, small additions"; 67.0% of Claude Code files are revised across multiple commits, median 23.8 h between context-file commits for Claude Code (22.3 h Codex, 68.0 h Copilot), and "content deletions are negligible" (Chatlatanagulchai et al., TOSEM 2025, Agent READMEs, [Agent READMEs: An Empirical Study of Context Files for Agentic Coding](https://arxiv.org/abs/2511.12884), §4.2 and Conclusion, via the arXiv MCP). Same direction as Chakrabarti (already cited).
- SOURCED: a dataset of 99K+ agent-file histories (274K+ revisions) from 20K+ repositories exists for longitudinal work (Cardoen et al., GHAgentFiles, ICSME 2026, [ICSME 2026 presentation - GHAgentFiles: A dataset of coding agent file histories in GitHub repositories](https://doi.org/10.6084/m9.figshare.33855373), presentation abstract only). A registered report on how agent-file change types relate to code quality is planned but has no results yet (Voria et al. 2026, [How Do Developers Maintain and Evolve Their Agents' Instructions? An Empirical Study](https://arxiv.org/abs/2606.25257), abstract). 12,110 `.cursorrules` files sit mostly in small, single-maintainer repositories (Sun et al., ICSOFT 2026, [A Study of Cursorrules Files in GitHub Open Source Projects](https://arxiv.org/abs/2608.10622), abstract).
- SOURCED: in 557 SWE-chat agent sessions (3,033 documentation interactions), instruction files and working notes were 60.5% of the documentation agents touched, against 10.6% for classical docs; "documentation trails code": in multi-commit PRs that change both, code is touched first 4.7x more often; no documentation-based validation sequence was observed (Gao and Chen 2026, [From Agent Behaviour to Agent-Friendly Documentation: An Empirical Study of How Coding Agents Discover, Read, and Write Technical Documentation](https://arxiv.org/abs/2608.20195), abstract; models not named there).
- Implication (BELIEVED): an agent-run repository changes its instruction surface about every two weeks or faster, almost only by appending. Drift checks must run on every merge, not quarterly. The append-only habit is itself a drift source, since removing a stale line is the rare edit.

### F2. Referential rot in context files: common, slow to be noticed, and naive checks have low precision
- SOURCED: an unmodified README/wiki checker (DOCER) found stale code-element references in **23.0% of 356 repositories (95% CI 18.8-27.2%)**, across 612 context files. 1.27% of the 18,048 verified references were stale; the median affected repository had 1 stale reference (max 20). By hand, **64% of 50 sampled flags were genuine, 24% false positives, 12% ambiguous** (one annotator). The two-snapshot criterion (reference valid at the file's first commit, gone at HEAD) misses rot added by later edits (Treude and Baltes 2026, Context Rot, [Context Rot in AI-Assisted Software Development: Repurposing Documentation Consistency for AI Configuration Artifacts](https://arxiv.org/abs/2606.09090), Tables 1-3).
- VERIFIED ([refrot.py](#scripts), [stale_age.py](#scripts)): the same two-snapshot idea restricted to backticked path tokens, on the 106 files of F1. It flagged 27 tokens in 13 repositories (12.3%). Every flag was checked by hand against the HEAD tree: **9 of 27 genuine (33%)**, in **7 of 106 repositories (6.6%)**. The false positives fell into four classes. 9 were deliberate "v4 removed X / do not reintroduce X" notes. 6 were files generated at install time, gitignored or user data. 2 lived outside the repository (an installed package, a private repository). 1 was an import specifier. The genuine paths had last been touched (moved or deleted) 0, 20, 153, 157, 157, 233 and 303 days before 2026-10-19, so **4 of 7 had been wrong for 5 months or more** in actively edited files. 341 further path tokens never resolved at either snapshot and were not inspected.
- Implication (BELIEVED): a path-existence check is worth having, but **as a gate it needs an explicit escape for intentional negative references** (the largest false-positive class) and for generated paths. H's existing dangling-path gate already covers part of this; a two-snapshot variant over memory and skills is the cheap extension. Neither number measures semantic rot (a claim about behaviour that is no longer true), which is the harder and more common class (F4).

### F3. Stale context misleads models more than missing context does
- SOURCED: outdated retrieved evidence flipped 30% of Llama and 37% of Qwen answers that were correct without retrieval. Told to follow the document, the flip rate rose to 66% and 75%. Across four open models and four domains the range was 17-91%. When told explicitly *when* the old evidence stops applying, the larger models switched almost perfectly, while a date alone produced "only modest adaptation" (Ahmed, Galke Poech and Röttger 2026, Stale-Document Poisoning, [Stale-Document Poisoning: When Outdated Retrieval Overrides Correct Model Answers](https://arxiv.org/abs/2609.31342), abstract and §1; 12 models incl. Qwen2.5-7B/72B, Llama-3.1-8B/70B, GPT-4o, GPT-4.1, plus a GPT-5.5 stress test).
- SOURCED: outdated comments may "mislead generation rather than simply degrade it" in LLM code completion (Xia et al., ASE 2026, [When Comments Mislead: An Empirical Study of Outdated Comments in LLM-Based Code Completion](https://doi.org/10.1145/3832783.3834359), abstract only; the full text was refused and no numbers were read).
- SOURCED: over 105 release transitions in 57 repositories, every release invalidated part of a frozen skill set (median 92 stale lines per transition). Six frontier agents updating the skills from the official patch reached **29.9-69.7% macro F1**. Best was Claude-opus-4.6 (F1 69.7, precision 75.7, recall 70.4); GPT-5.4 had the highest recall (74.6) but 55.7 precision and 44% off-target edits (Duan et al. 2026, Repo2Skill-Evo, [Repo2Skill-Evo: Repository Skills Go Stale in Silence](https://arxiv.org/abs/2608.21964), Tables 2 and 4). The title states the mechanism: "repository skills go stale in silence."
- SOURCED: inconsistent code-comment changes were about **1.5x more likely** to lead to a bug-introducing commit, and the effect was largest right after the inconsistency appeared (Radmanesh et al. 2024, [Investigating the Impact of Code Comment Inconsistency on Bug Introducing](https://arxiv.org/abs/2409.10781), abstract; classifier: fine-tuned GPT-3.5).
- Contrary (SOURCED elsewhere): context files barely move task success (Gloaguen et al. 2026, [Evaluating AGENTS.md: Are Repository-Level Context Files Helpful for Coding Agents?](https://arxiv.org/abs/2602.11988), already in [harness-efficiency.md](../../harness-efficiency.md); Khatri, already cited). BELIEVED reconciliation: the harm of a stale line is bounded by how much agents rely on the file. Owner-policy and procedure lines (commands, paths, "never X") are followed ("instructions in the context files are well followed", Gloaguen abstract), so those are where staleness costs the most.
- Implication (BELIEVED): an entry that is superseded should say so explicitly ("superseded by #N on date; now Y") rather than carry a date only. Agents must not be asked to update skills from a diff unaided: even the best model left ~30% of stale lines or over-edited. Skill and agent bodies need derived content or a gate that names the lines touched by a change.

### F4. Classic doc and comment rot: base rates, timing and detector precision
- SOURCED: 97% of comment changes happen in the same revision as the associated code change (Fluri, Würsch and Gall, WCRE 2007, [Do Code and Comments Co-Evolve? On the Relation between Source Code and Comment Changes](https://doi.org/10.1109/wcre.2007.21), abstract; 3 Java systems). So prose that is not fixed in the same commit is rarely fixed later, which argues for a commit-time (just-in-time) check over a later sweep (BELIEVED).
- SOURCED: the largest co-evolution study (1.3 billion AST-level changes, 1,500 systems, 500 commits coded by hand) gives a taxonomy of the inconsistencies developers fix, and shows which code-change types trigger comment updates (Wen et al., ICPC 2019, [A Large-Scale Empirical Study on Code-Comment Inconsistencies](https://doi.org/10.1109/icpc.2019.00019), abstract only; no rates read).
- SOURCED, detector precision on one cleaned benchmark (Xu et al. 2023's numbers as tabulated in Radmanesh et al., Table 2): the deep just-in-time detector of Panthaplackel et al., AAAI 2021, [Deep Just-In-Time Inconsistency Detection Between Comments and Source Code](https://arxiv.org/abs/2010.01625) reached **60.6% precision / 35.4% recall**, and the rule-based Fraco 19.5% / 15.4%. Fine-tuned GPT-3.5 reached 90.97% / 96.38%, but zero-shot only 68.6% / 45.8%. CoCC claims ">90%" precision (Huang et al. 2024, [Are your comments outdated? Towards automatically detecting code-comment consistency](https://arxiv.org/abs/2403.00251), abstract). A fine-tuned CodeLLaMA's comment rewrites were right 65.0% (just-in-time) and 55.9% (post hoc) of the time (Rong et al., ICSE 2025, [Code Comment Inconsistency Detection and Rectification Using a Large Language Model](https://doi.org/10.1109/icse55347.2025.00035), abstract).
- SOURCED: an LLM README-update recommender, run on 25,511 PRs from 714 repositories, recovered half of the PRs that historically came with README updates. It reached **28% user-facing accuracy at the observed prevalence**, and 21.5% of its retrospective recommendations (6.1% at the most conservative reading) found updates developers had missed (Gao et al. 2026, [Does My README File Need To Be Updated? Exploring LLM-Based README Maintenance](https://arxiv.org/abs/2603.00489), abstract).
- Implication (BELIEVED): semantic detectors sit at about 30-75% precision once prevalence is realistic (READU 75%, already cited; Gao 28%). This confirms §6 of the parent note: semantic checks are sweep inputs, never gates.

### F5. Agent memory: models are poor at noticing that a stored fact is stale
- SOURCED: on 400 implicit-conflict scenarios (a later observation invalidates an earlier memory without saying so), the best model, Gemini-3.1-pro, scored **55.2% overall**. GPT-5.4 scored 15.7%, Qwen3.5-27B 31.3%, and the dedicated memory frameworks (mem0, Zep, A-mem, LiCoMemory) 5-8%. "Premise resistance" (rejecting a query that assumes the stale state) was 0-30% for every off-the-shelf system. A write-time consolidation prototype reached 68.0% (Chao et al. 2026, STALE, [STALE: Can LLM Agents Know When Their Memories Are No Longer Valid?](https://arxiv.org/abs/2605.06527), Table 2).
- SOURCED: in MemoryAgentBench's FactConsolidation task, which states that newer facts have larger serial numbers, the best of 22 reported systems scored 54% single-hop and none above 7% multi-hop. Separating evidence extraction from answer policy raised single-hop accuracy by 10.8 pp on average, but with no significant gain on LongMemEval (26/45 vs 29/45, McNemar p = 0.45) (Reddy and Challaram 2026, [Reliable Post-Retrieval Assembly for Agent Memory: Separating Evidence Extraction from Policy Execution](https://arxiv.org/abs/2606.01435), abstract; gpt-4o-mini, gpt-4o; benchmark: Hu, Wang and McAuley 2025, [Evaluating Memory in LLM Agents via Incremental Multi-Turn Interactions](https://arxiv.org/abs/2507.05257)). LongMemEval reports a 30% accuracy drop over sustained interactions, with knowledge updates as one of its five abilities (Wu et al., ICLR 2025, [LongMemEval: Benchmarking Chat Assistants on Long-Term Interactive Memory](https://arxiv.org/abs/2410.10813), abstract).
- SOURCED, operational record (N = 1, self-reported, no control): one months-long Claude Code project with an instrumented memory subsystem logged 85 recorded failures over 78,933 hook invocations, **84 of them in the first three weeks** ([Helwig 2026](https://arxiv.org/abs/2609.05510), abstract). A six-month self-study of an event-log memory found that 86 of 427 fixed issues had a failed attempt before the fix, as candidates for repeat-failure warnings; the authors do not claim the warnings prevented anything (Malo and Qiu 2026, [PROJECTMEM: A Local-First, Event-Sourced Memory and Judgment Layer for AI Coding Agents](https://arxiv.org/abs/2606.12329), abstract).
- SOURCED, platform: Claude Code auto memory loads the first 200 lines or 25 KB of MEMORY.md every session. Near the limit Claude is reminded to "merge or drop stale entries", and nothing expires on its own ([memory docs](https://code.claude.com/docs/en/memory), fetched 2026-10-19). The API memory-tool docs advise: "Periodically delete memory files that haven't been accessed in a long time," cap file sizes, and validate paths ([memory tool docs](https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool), fetched 2026-10-19).
- Implication (BELIEVED): do not rely on the model to notice that a memory entry has gone stale. That is the measured weakness (premise resistance near 0 for most systems). Use mechanisms instead: (a) each entry names the repo fact it depends on (a path, issue, rule or command) so a sweep can check it mechanically; (b) supersession is written explicitly (F3); (c) an orient-time listing puts every entry in front of the lead (already proposed in the parent note §7.4). Expect failures early in a memory mechanism's life (Helwig), so measure it in its first weeks.

### F6. Memory poisoning is a drift path with a security edge
- SOURCED: persistent-memory poisoning through benign-looking external sources, tested on **Claude Code** and OpenClaw with DeepSeek-V4-Flash, DeepSeek-V4-Pro and Qwen3-Max backbones (not Claude models). On Claude Code the injection success rate was 66.9% and the cross-session attack success rate 81.7%. A first-person payload raised injection from 48-54% to 83%. A sandwich prompt defence cut injection in many settings but gave "limited protection once the persistent memory has been poisoned" (Huang, Zhang and Jia 2026, PMPA, [When Malicious Instructions Persist: Persistent Memory Poisoning Attack on Harness-Based Agents](https://arxiv.org/abs/2609.13889), Table 1, §4.2-4.3).
- SOURCED: poisoning 1.2% of a LongMemEval corpus with plain false assertions cut accuracy from 0.850 to 0.300. A write-time screen with 0.832 recall on prompt injection **rejected 0 of 360 poisoned memories**. The paper's conclusion: telling true from false needs external grounding ([Karunanidhi 2026](https://arxiv.org/abs/2608.21230), abstract).
- SOURCED, platform: Claude Code 2.1.284 began neutralising invisible characters and markup-imitating tags in MEMORY.md and recalled notes ([CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md), fetched 2026-10-19).
- Implication (BELIEVED): a content linter cannot catch a false memory entry; only provenance and grounding can. Each memory entry should record its source (owner message, issue, or web page). Entries sourced from the web should not count as owner decisions, and the orient listing should show the source. This matters more for downstream projects with strict security requirements.

### F7. Upstream platform and model drift is continuous
- VERIFIED ([cc_cadence.py](#scripts) over the Claude Code CHANGELOG fetched 2026-10-19, plus `gh api` commit dates): **155 Claude Code versions shipped between 2.1.117 and 2.1.304 in the six months from 2026-04-19**, about 26 a month. Commits to CHANGELOG.md ran 25-32 a month from May to September. Of 5,648 changelog bullets in that window, 423 begin with Removed / Changed / Deprecated / Renamed / Breaking, and 193 of those mention a harness surface (settings, hooks, skills, agents, memory, permissions, plugins, env, CLAUDE.md), about 1.25 per version. 13 are strict Removed / Deprecated / Renamed on those surfaces, such as the deprecated TaskOutput tool and its `taskOutputMaxChars` setting, a `/config` setting, and CLI flags. Keyword classification, not hand-checked.
- SOURCED, model drift: the "same" GPT-4 service fell from 84% to 51% on prime identification between March and June 2023, partly because it followed chain-of-thought prompts less (Chen, Zaharia and Zou 2023, [How is ChatGPT's behavior changing over time?](https://arxiv.org/abs/2307.09009), abstract). That evidence is old and on another provider; it shows the mechanism, not today's rate.
- SOURCED, dependency practice: technical lag in npm grows over time across 1.4M releases (Decan, Mens and Constantinou, ICSME 2018, [On the evolution of technical lag in the npm package dependency network](https://arxiv.org/abs/1806.01545), abstract). Dependabot adoption reduces technical lag, but developers configure it to cut notifications, and 11.3% of projects abandoned it (He et al., TSE 2023, [Automating Dependency Updates in Practice: An Exploratory Study on GitHub Dependabot](https://arxiv.org/abs/2206.07230), abstract). The lesson for a template pin is that an update bot works when its noise is budgeted (BELIEVED).
- Implication (BELIEVED): at ~26 releases a month, a harness that depends on settings keys, frontmatter fields or hook semantics will meet about one relevant platform change per working day. Reading the docs by hand cannot keep up. The cheap mechanisms are: a pinned schema linter on settings and frontmatter run in the gate; a weekly sweep that diffs the changelog's Removed/Deprecated lines against the keys the harness uses; and recording the Claude Code version in every measurement.

### F8. Tools: what exists, what it costs, how precise it is
- SOURCED: Claude Code now ships an LLM auditor. `/doctor prompt-audit` (v2.1.283+) audits CLAUDE.md, AGENTS.md, rules, skills, commands and subagents for "instructions written for older models, references to files or commands that don't exist, and files that contradict each other". It reports and proposes edits but changes nothing on its own ([memory docs §Audit your instruction files](https://code.claude.com/docs/en/memory); CHANGELOG 2.1.283). No precision figure is published. The docs also tell users to "Review your CLAUDE.md files ... periodically to remove outdated or conflicting instructions".
- SOURCED: ContextCov compiles AGENTS.md rules into AST queries, shell shims and architecture validators. On SWE-bench Lite (300 tasks, 12 repositories) it reached 88.3% constraint compliance, against 67.0% for prompt-only and 50.3% for LLM reflection, at 3.4x lower feedback cost. Its semantic checks are warnings only, "to reduce unsafe false positives"; checks are generated with Claude Code and Opus 4.5 ([Sharma 2026](https://arxiv.org/abs/2603.00822), abstract, §2.3.2, §3.3). Repository: [reSHARMA/ContextCov](https://github.com/reSHARMA/ContextCov), 1 star, MIT, pushed 2026-09-05, so a research prototype.
- VERIFIED via the GitHub API on 2026-10-19:
  - [agent-sh/agnix](https://github.com/agent-sh/agnix): agent-config linter, 702 rules (170 for Claude Code: CLAUDE.md, rules, settings, hooks, agents, skills, plugins), 455 stars, Apache-2.0, pushed 2026-10-18. Precision unmeasured.
  - [nedbat/cog](https://github.com/nedbat/cog): generated-in-place docs with `--check` for CI. 407 stars, MIT, pushed 2026-10-19; PyPI `cogapp` 3.6.0.
  - [vale-cli/vale](https://github.com/vale-cli/vale): prose style linter. 6,258 stars, MIT.
  - [tcort/markdown-link-check](https://github.com/tcort/markdown-link-check): 721 stars, ISC.
  - [modal-labs/pytest-markdown-docs](https://github.com/modal-labs/pytest-markdown-docs) (86 stars, MIT) and [koaning/mktestdocs](https://github.com/koaning/mktestdocs) (161 stars, Apache-2.0, last push 2025-11): executable code blocks in Markdown.
  - Swimm (code-coupled docs) is commercial and was not checked.
- Implication (BELIEVED): agent-harness should not build its own LLM drift auditor. It can schedule `/doctor prompt-audit` as a sweep input whose findings become issues, and measure its precision on held-out history before trusting it. For deterministic checks, the template's own derive-and-check pattern (`uv run dev docs` plus gate) already is the cog pattern; extend it rather than adopt cog. agnix is worth a `reuse check` as a candidate pinned platform-schema linter for class (3).

### F9. What Anthropic's long-running-agent posts actually say about drift
- SOURCED: [Effective harnesses for long-running agents](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents) (2025-11-26, Opus 4.5 on the Agent SDK). It names four failure modes: one-shotting, leaving undocumented half-done state, declaring victory early, and marking features done without end-to-end tests. Its mechanisms: an initializer session; a JSON feature list (200+ features, all initially failing) in which agents may change only `passes`, chosen because, per the post, the model is less likely to overwrite JSON inappropriately than Markdown (paraphrase); `claude-progress.txt`; descriptive git commits; `init.sh`; and a session-start routine that reads the git log and progress file and runs a basic end-to-end test before new work. **No quantitative results** are given.
- SOURCED: [Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) (2025-09-29) describes context rot as a "performance gradient rather than a hard cliff", plus structured note-taking (NOTES.md) and just-in-time retrieval. It gives no numbers and **no guidance on stale notes**. The [context-management announcement](https://claude.com/blog/context-management) (2025-09-29) reports +39% (memory tool plus context editing) and +29% (context editing alone) on "an internal evaluation set for agentic search", and an 84% token cut on a 100-turn web-search eval. Model and N are not stated.
- SOURCED: the [memory tool docs](https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool) give the multisession pattern: an initializer session sets up a progress log and feature checklist, and each session ends by updating the log. "Mark a feature complete only after end-to-end verification confirms it works ... This keeps the progress log accurate from session to session."
- Implication (BELIEVED): Anthropic's answer to drift in long runs is structural. The state file can only be changed in a narrow way (`passes`), and verification runs at session start. It is not a semantic check. That matches H's choice of DONE WHEN ticks written by integrate (parent note §7.4) and argues for a session-start smoke check in `orient`. None of it is measured.

## Gaps seen, not closed
- No study measures **time-to-detection** of stale agent instructions. Only the ages of the 7 genuine stale paths here (0-303 days) bound it, and they are right-censored (still undetected).
- No precision figure for `/doctor prompt-audit` or agnix. Both are cheap to measure on H's replay history.
- The 341 unresolved path tokens in F2 were not inspected; some are rot that the two-snapshot rule misses (added after the file's first commit).
- Xia et al. (ASE 2026) full text was refused, so there is no effect size for stale comments misleading code completion. GHAgentFiles was read as a presentation abstract only.
- No outside study of auto-memory files (Claude Code MEMORY.md) in the wild; the r1-memory round covers local data.
- The CHANGELOG keyword classification (F7) was not hand-checked; a 30-bullet sample would give its precision.
