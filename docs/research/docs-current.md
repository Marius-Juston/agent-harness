Status: v1 (2026-11-19). Issue: #497. Extends [decision-records-and-drift.md](decision-records-and-drift.md) (drift of specs, docstrings and instruction files) with where agents actually lose time to missing or stale docs, and which documentation mechanisms pay for their tokens.

## 0. Findings in one paragraph
Missing or stale documentation is a small, concentrated cost, and none of it calls for more always-loaded text. In 752 runs (H 87, repo-S 484, repo-V 181; 2026-10-20 to 11-19), failing calls a doc, docstring, help text or setup note could have prevented were 0.20-0.47% of all tool calls, and their recovery took 0.22-0.55% (upper bound with every unexplained path miss: 0.68-1.13%). Almost every miss is repaired in one call, within seconds. The cost is concentrated in a few recurring clusters, each repeated across many runs: in repo-S, 67 failing calls in 58 of 484 runs (12%) built one undocumented project class with missing fields, and 101 calls hit tools or packages the environment does not have (scipy and similar, `ty`, a worktree without `node_modules`). In H the misses are 8 guessed `uv run dev` flags or subcommands and 4 guessed module paths (`devkit/integrate.py`, `devkit/doctor.py`). Builders orient with code, not docs: the median builder makes 14-26 calls before its first edit, 41-48% of them searches and 6-15% doc reads. Always-loaded text is the expensive option. Every always-loaded word is re-read on every turn, about 4,700 tokens per word over H's window and 51,000 in repo-S's. A generated module map imported into CLAUDE.md (514 words for devkit) would spend about 9 times the tokens it could save in H, and the outside evidence agrees: repository overviews do not raise task success (Gloaguen et al. 2026, [Evaluating AGENTS.md: Are Repository-Level Context Files Helpful for Coding Agents?](https://arxiv.org/abs/2602.11988)), and compact documentation did not beat the issue alone when the source was present (Arman and Molybog 2026, [Compact Documentation for Coding Agents: A Benchmark, an Optimizer, and Why It Does Not Transfer](https://arxiv.org/abs/2609.31587)). Ranked by time saved per always-loaded token, adopt three zero-token mechanisms. (1) A recurring-failure report from transcripts (`dev agent-stats --recurring`) finds the clusters above without any reading. (2) `uv run dev` names the subcommand's own usage and the nearest flag when an argument is wrong. (3) A ratchet on undocumented public classes (ruff D101) puts docstrings where an agent reads them on demand. Offer AGENTS.md as a template option: Claude Code reads it natively since v2.1.277, and other tools share the same file, so it adds no tokens. Reject llms.txt (a website convention: 97% of domains with the file received no recorded requests), a whole-tree docstring-coverage gate, a doctest gate, and any always-loaded map.

## 1. Question and scope
The question ([#497](https://github.com/Marius-Juston/agent-harness/issues/497)): where did agents in this repository lose time to missing or stale docs, and which of these candidates keep documentation current for agents and humans: a generated architecture or module map, a docstring-coverage ratchet (interrogate, ruff D rules), docs-as-tests (doctest), llms.txt, AGENTS.md as the cross-tool convention, and short agent instructions? Owner (2026-11-19, via the lead): "we want a high effectiveness + low token usage system". So prefer documentation read only when needed (generated, scoped, short) over always-loaded text, measure the always-loaded token cost of every proposal, and rank by time saved per token. Out of scope, with their own issues: drift sweeps of specs and docstrings ([#299](https://github.com/Marius-Juston/agent-harness/issues/299)), decision-level drift ([#238](https://github.com/Marius-Juston/agent-harness/issues/238)), and code search or repo maps ([#495](https://github.com/Marius-Juston/agent-harness/issues/495)).

Data: every transcript still on the research machine (kept 30 days) for the three harness-run repositories: H 87 runs (3 main sessions, 84 subagents, 4,029 tool calls), repo-S 484 runs (42,400 calls), repo-V 181 runs (about 16,000 calls). These are VERIFIED counts from [tx_docs.py](_scratch/docs-current/scripts/tx_docs.py) and [coded.py](_scratch/docs-current/scripts/coded.py). The corpora grow while sessions run (this research run is in H's), so recounts move by a few calls. One rater coded every cluster.

## 2. Where agents lost time (VERIFIED, one rater)
### 2.1 Method
- [tx_docs.py](_scratch/docs-current/scripts/tx_docs.py) reads each transcript's tool calls in order and classes each failing result: a guard refusal, a CLI usage error, a missing path, a Python API error, a gate failure or other. The output of a read or search (grep, cat, Read) counts only when the call itself errored, because file text quotes failure strings. It also records the calls and minutes until the next call that does not fail (the recovery cost), and the calls before each builder's first Edit or Write (orientation).
- [recurring.py](_scratch/docs-current/scripts/recurring.py) groups failures into signatures (the key error line, with paths, numbers and quoted values masked) and lists those seen in at least 3 runs.
- I read every CLI, API and path candidate in H (95 rows) and samples of repo-S (40 path, 20 API) and repo-V (25 path, 13 CLI). I then wrote one pattern per cluster in [coded.py](_scratch/docs-current/scripts/coded.py), so the counts below reproduce. The private dumps stay out of the repository.

### 2.2 Doc-preventable failures are under 0.5% of calls
| cluster (code in coded.py) | H calls / runs | repo-S calls / runs | repo-V calls / runs | doc-preventable? |
|---|---|---|---|---|
| project class constructed with missing fields (no docstring, no loader) | 1 / 1 | **67 / 58** | 0 | yes: a class docstring or a `from_` helper |
| third-party package not installed (scipy, sympy, mpmath ...) | 0 | **58 / 53** | 7 / 5 | yes: a setup or dependency line |
| worktree without `node_modules` | 1 / 1 | 30 / 29 | 2 / 2 | yes: worktree setup |
| tool not installed: `ty` | 3 / 3 | 13 / 13 | 16 / 16 | yes: install it or stop suggesting it |
| guessed `uv run dev` flag, subcommand or missing argument | **8 / 7** | 1 / 1 | 4 / 2 | yes: help text |
| guessed flag of another CLI (gh `--json` field, uv, pytest) | 2 / 2 | 1 / 1 | 3 / 3 | partly |
| guessed module path (`devkit/integrate.py`, `devkit/doctor.py`) | 4 / 4 | 0 | 0 | yes: a module map or command-to-module line |
| **doc-preventable total** (failing / recovery calls) | 19 / 22 | 170 / 199 | 32 / 35 | |
| share of all calls (failing / recovery) | 0.47% / 0.55% | 0.40% / 0.47% | 0.20% / 0.22% | |
| project module not importable (python3 run outside `uv run`) | 6 / 4 | 9 / 9 | 50 / 46 | no: a rule already says uv only |
| doc-link gate caught a stale path | 3 / 3 | 15 / 14 | 0 | no: the check working |
| other path misses (layout guesses, own scratch files, environment) | 23 / 16 | 308 / 216 | 76 / 53 | mixed; upper bound |

Shares and token equivalents are from [synth_arith.py](_scratch/docs-current/scripts/synth_arith.py). With every unexplained path miss counted as a doc miss, the upper bound is 1.04% of calls in H, 1.13% in repo-S and 0.68% in repo-V.
- **Recovery is one call.** The median recovery is 1 call and 5-10 seconds in every class and corpus ([tx_docs.py](_scratch/docs-current/scripts/tx_docs.py) part B). The doc-preventable recovery calls re-read about 1.4M context tokens in H, 33.8M in repo-S and 4.7M in repo-V, mostly as cache reads. Median builder context per turn is 65k, 170k and 134k tokens ([turn_cost.py](_scratch/docs-current/scripts/turn_cost.py)).
- **The costly misses recur.** Recurring signatures (at least 3 runs) cover 2,333 of 2,542 failing calls in repo-S. The one large documentation cluster is a project class whose constructor needs fields that the data file it is built from often lacks. 58 builders each rediscovered this, and the class has no docstring: repo-S's public classes are 86% documented, and this is one of the 8 that are not ([doc_coverage.py](_scratch/docs-current/scripts/doc_coverage.py)). The environment clusters (`ty`, scientific packages, `node_modules`) are setup gaps, not prose gaps. A setup line or a dev dependency closes each of them once. Where agents learn to call `ty` is not in any harness or template file (BELIEVED: a user-level skill suggests it; unverified).
- **H's misses are CLI and layout guesses.** The 8 `uv run dev` guesses include `board wave -n 8` (also seen in repo-V), `board show`, `worktree --dry-run` without a subcommand, `test -k`, `board claim` without `--agent`, and `code refs` with two names. repo-V adds `board beat --note`, `board new --priority` and `board block` with a positional reason. For an unknown flag the error shows the top-level usage (`usage: dev [-h] <command> ...`), not the subcommand's, so the agent then calls `--help` (VERIFIED from the transcripts). The module-path guesses come from command names that are not module names: `integrate` lives in `devkit/workflow.py` and `devkit/merging.py`, and `doctor` in `devkit/setup.py`. The gate's doc-link check caught 3 stale paths in H and 15 in repo-S at gate time, so the existing check works.
- **Stale docs, as distinct from missing ones, cost almost nothing at use time.** Agents remarked on a stale or wrong doc in 1-3 sentences per corpus (part D candidates). This agrees with the #282 finding that drift met at use time costs a call or two ([decision-records-and-drift.md](decision-records-and-drift.md) §10, §12).

| corpus | builder runs with an edit | median calls before first edit | median minutes | search | code read | doc read | brief/orient | `dev code` nav |
|---|---|---|---|---|---|---|---|---|
| H | 41 | 14 | 1.7 | 48% | 16% | 8% | 10% | 6% |
| repo-S | 148 | 19 | 2.4 | 41% | 11% | 15% | 8% | 0% |
| repo-V | 57 | 26 | 4.9 | 45% | 22% | 6% | 9% | 4% |

The H column of this table is a 2026-11-19 snapshot from [tx_docs.py](_scratch/docs-current/scripts/tx_docs.py) part A. In H, 89 of 293 pre-edit searches grep for a `def` or `class` (symbol lookup, the domain of #495), and 197 look for usages or strings. The docs H builders read before editing are CHANGELOG.md (11 reads), docs/specs/multi-agent.md (9) and SETUP.md (4); none read docs/generated/agent-surface.md. Orientation is a fixed cost of 2-5 minutes, not a loss: no metric here separates necessary reading from reading a map would have replaced, so savings from a map are unmeasured (BELIEVED to be a fraction of the search share).

## 3. The candidates, ranked by time saved per always-loaded token
**Always-loaded cost (VERIFIED arithmetic, [synth_arith.py](_scratch/docs-current/scripts/synth_arith.py)).** CLAUDE.md and its imports load into every session and subagent and sit in the prefix of every turn. One added word therefore costs about 1.33 tokens (ASSUMED ratio) times all turns: about 4,700 tokens over H's window (3,508 turns), 18,000 in repo-V's and 51,000 in repo-S's. The doc-preventable recovery calls of H's whole window re-read about 1.4M tokens. 300 always-loaded words cost about as much as every doc miss H had.

|---|---|---|---|---|

Python 3.14's `suggest_on_error` covers only choices and subcommand names, not unknown flags ([argparse docs](https://docs.python.org/3/library/argparse.html), SOURCED) | **adopt** (build issue) |

| 8 | doctest (`--doctest-modules`) as a gate | 0 | doctest checks "that a module's docstrings are up-to-date by verifying that all interactive examples still work as documented" ([doctest docs](https://docs.python.org/3/library/doctest.html), SOURCED), but no failure here traced to a stale docstring example, and devkit's docstrings carry none | **not now**; allowed per project for new examples |
| 9 | whole-tree docstring coverage gate (interrogate, all D1 rules) | 0 | coverage is already 69% (devkit), 77% (repo-S) and 73% (repo-V) of public symbols; interrogate is dormant (HOLD G4: 957 days since release), ruff covers the same rules with no new dependency (`dev reuse check`, VERIFIED) | **reject**; class ratchet (3) instead |
| 10 | llms.txt | 0 here; it is a website file | the proposal is "a /llms.txt markdown file to websites" ([llmstxt.org](https://llmstxt.org/), SOURCED); one audit found 97% of domains with the file received no recorded requests, and no source isolated a utility effect (Qian et al. 2026, [Manifest-Assisted Retrieval in Artificial Intelligence Search: Evidence Gaps and a Security Evaluation](https://arxiv.org/abs/2610.38361), SOURCED abstract); Claude Code does not read it from a repository (BELIEVED, not in the memory docs) | **reject** |

Documentation debt compounds in agent work generally: 63.2% of 29,669 AI-generated PRs changed code without updating any documentation, and a file changed without documentation was re-documented within 90 days at about half the rate (24% vs 48%) (De Michele and Tantithamthavorn 2026, [Documentation Drift in AI-Generated Pull Requests](https://arxiv.org/abs/2610.27381), SOURCED abstract). Item 3 addresses the class-level part of that debt at the place agents read. The drift of existing docstrings stays with #299's advisory sweep.

## 4. Recommendation for this project
1. **Build `dev agent-stats --recurring`** (generic: it reads the project's own transcripts). It lists failure signatures seen in at least 3 runs in the window (default 14 days), with runs, calls, recovery calls and minutes. It withholds nothing, since a project reads its own transcripts, and it masks paths and numbers as [recurring.py](_scratch/docs-current/scripts/recurring.py) does. The lead reads it in the consolidation or suite-audit cadence, never at orient, so it does not add a standing warning (warning decay, [decision-records-and-drift.md](decision-records-and-drift.md) §12, [#298](https://github.com/Marius-Juston/agent-harness/issues/298)). Target: on the snapshot fixtures it reproduces the repo-S clusters of §2.2 (class constructor, packages, `ty`, `node_modules`) within ±10% of the counts. Each cluster at or above 10 runs becomes one board item.
2. **Build `uv run dev` usage errors that teach.** An unknown option or missing argument under a subcommand prints that subcommand's usage line and, when difflib finds one at ratio 0.6 or higher, "did you mean `--prio`?". Target: the 12 historical guesses of §2.2 (H 8, repo-V 4) each get the right usage line from the first error; 0 always-loaded words.
3. **Ratchet D101 (undocumented public classes)** in the gate: count `ruff --select D101` per project, store it in `.devkit/ratchets.toml`, refuse a rise, and let integrate write a fall. Start at today's count (17 in devkit). Do not ratchet D102/D103: 176 findings here, and no measured cluster behind them. The template inherits the ratchet with the project's own count.
4. **AGENTS.md option** in the template (copier question, default off): project rules in AGENTS.md, CLAUDE.md holding `@AGENTS.md` and the harness import. The context budget counts AGENTS.md once, `check_links` follows the import, and render_check passes both ways.
5. **No new always-loaded documentation.** A generated module map, an llms.txt, and a doctest or full-coverage gate are rejected for the reasons in §3. Re-open the map only if #495's measured repo map wins and is served on demand.
6. **Per project, not template**: repo-S and repo-V should add `ty` (or stop suggesting it), their scientific packages and their worktree `node_modules` step. These are owner actions in those projects; item 1 surfaces them in any project.

What would change this: a recurring cluster that a doc line, but no helper, check or setup step, could close; a measured orientation saving from a map on held-out tasks (#495); or a second downstream project where class docstrings show no link to recurring API failures (then drop item 3).

## 5. Limits
- 30 days of transcripts on one machine; H's window is small (87 runs). repo-S dominates the totals, and its largest cluster is one class.
- One rater wrote every code. The "other path misses" bucket was sampled (40 + 25 rows), not read in full, which is why it is reported as an upper bound.
- Recovery cost counts calls until the next non-failing call. It misses silent misuse (a wrong but successful call) and work an agent redid without an error.
- Token conversion uses median builder context per turn and an ASSUMED 1.33 tokens per word; cache-read pricing makes tokens cheaper than they look, but the always-loaded side of the comparison uses the same unit.
- Outside sources were read as abstracts; none was replicated. The 60k-projects figure is the AGENTS.md site's own.
