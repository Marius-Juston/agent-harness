## 0. Findings in one paragraph
The harness already has most of what peer systems sell as their core: a capped, symbol-level agent-computer interface (SWE-agent's main result), lint at edit time (aider, SWE-agent), a gate that re-runs on the merged tree, worktree isolation, race-safe claims across machines and per-role effort. The owner's goal is high effectiveness at low token use, so gaps are ranked by expected effect per token. On this machine's 30-day window, **$176.86 modelled over 76 merged PRs ($2.33 each): builders 56 %, the lead 24 %, researchers 13 %, reviewers 4 %; only 55 % of spend attributes to an issue** (VERIFIED, [cost_tail.py](_scratch/gap-survey/scripts/cost_tail.py)). So the largest token levers are the lead's mechanical turns (#499) and builder rework from parallel collisions (#507), and the largest effectiveness lever is review and acceptance tests that make "met" checkable (#501, #503). Measurement comes first: OpenTelemetry gives exact per-request cost by agent, effort and model, which transcripts cannot (#502). The gaps no one had filed are **security gaps that cost no tokens**. guard_bash lets a builder run `gh pr merge --admin`, `gh repo edit --visibility public`, branch-protection writes and `gh gist create` (VERIFIED, [probe_write_caps.py](_scratch/gap-survey/scripts/probe_write_caps.py); filed as #528). Nothing states or checks the Claude Code version the fail-closed guards need (filed as #530). Bash can write `.claude/settings*.json` past edit_guard, which a ConfigChange hook would block (posted on #191). Prompt-level defences such as spotlighting (#56) fall to adaptive attacks at over 50 % success, while harness-level capability scoping cut injected effects from 33-47 of 75 runs to 3 of 75 (SOURCED). So #528 and the sandbox (#509) come before #56, not after. Researcher and builder compaction, a per-issue spend cap, agent teams and an OpenHands-style condenser are not gaps here (§6).

## 3. Where the tokens go, and which gaps can move them
- **This repository, 2026-10-20..11-19 (VERIFIED, [cost_tail.py](_scratch/gap-survey/scripts/cost_tail.py) on `dev agent-stats --cost --json`).** $176.86 over 3,523 turns; 76 merged PRs, so $2.33 per merged PR. By type: builder 55 runs $99.27 (56 %), lead sessions 5 $42.55 (24 %), researcher 6 $22.64 (13 %), reviewer 17 $6.94 (4 %), the rest 3 %. Per issue with runs (46): median $1.31, p90 $3.78, max $12.51.
- **repo-E, 2026-10-11..16** (harness-efficiency.md §2): researcher 50 %, builder 23 %, lead 16 %. The mix depends on the project; the lead and the builders are large in both.
- **Lead.** Bookkeeping is 31.9 % of lead turns in repo-E ([issue-pr-automation.md](issue-pr-automation.md)). A deterministic iteration (#499) removes model turns instead of shortening them, so it saves tokens at zero risk to correctness when it refuses what integrate refuses (BELIEVED).
- **Builders.** Rework from collisions between parallel builders is the lead's reported cause of most 2026-11 send-backs (#507 body; not measured here). Review is 4 % of spend and found blocking defects in nearly every feature PR of 2026-11-01 (#501 body), so required review buys effectiveness cheaply (BELIEVED).
- **Unattributed spend.** 45 % of this window's cost has no issue, mostly lead sessions and shared runs. Per-issue numbers stay partial until runs carry an issue key; OTel events carry `agent_id`, the join key to transcripts (SOURCED, Monitoring; posted on #502).

## 4. Security: the zero-token gaps
- **Exposure is real but rarely used (VERIFIED, [untrusted_authors.py](_scratch/gap-survey/scripts/untrusted_authors.py)).** All 338 issues and 665 of 666 issue comments here are by the owner; one comment is by another login. The repository is public, and `brief` and `board feedback` show any author's comments.
- **What a steered worker can do (VERIFIED, [probe_write_caps.py](_scratch/gap-survey/scripts/probe_write_caps.py)).** For a `harness-ops:builder` payload, guard_bash allowed `gh pr merge` (also `--admin`), `gh issue close`, `gh issue edit` (enough to write an owner-looking `weakening-ok:` marker), `gh gist create --public`, `gh api -X DELETE` on a ref, `gh api -X PUT` on branch protection, `gh release create` and `gh repo edit --visibility public`. Its two `git push` controls were blocked, so the probe works. No harness guidance uses these commands, and `dev integrate` calls gh from Python, which PreToolUse does not see. Filed as **#528**.
- **Prompt-level defences are a layer, not the control.** Spotlighting cut attack success "from greater than 50 % to below 2 %" on GPT-family models ([Defending Against Indirect Prompt Injection Attacks With Spotlighting](https://arxiv.org/abs/2403.14720), Hines et al. 2024, abstract, SOURCED). Adaptive attacks bypassed all eight defences tested, "consistently achieving an attack success rate of over 50 %" ([Adaptive Attacks Break Defenses Against Indirect Prompt Injection Attacks on LLM Agents](https://arxiv.org/abs/2503.00061), Zhan et al. 2025, abstract, SOURCED). A capability-scoped harness let the injected effect execute in 3 of 75 runs against 33-47 of 75 for the baselines, completing 68 of 75 repairs against 68-72 ([Authority Is Not a String: A Capability-Scoped Harness for Prompt-Injection-Resistant Coding Agents](https://arxiv.org/abs/2609.08371), Bouras et al. 2026, abstract, SOURCED; 5 tasks, 300 runs, one agent, not Claude Code). Design patterns that constrain what an agent can do after reading untrusted text are the principled form ([Design Patterns for Securing LLM Agents against Prompt Injections](https://arxiv.org/abs/2506.08837), Beurer-Kellner et al. 2025, SOURCED abstract).
- **The pattern is common in the wild.** Agentic GitHub workflows that feed issue bodies, PR descriptions or comments into agent prompts: 496 confirmed exploitable of 519 flagged across 13,392 workflows ([Demystifying and Detecting Agentic Workflow Injection Vulnerabilities in GitHub Actions](https://arxiv.org/abs/2605.07135), Wang et al. 2026, abstract, SOURCED). A red-team set for #509 can borrow AgentDojo's task and attack structure ([AgentDojo: A Dynamic Environment to Evaluate Prompt Injection Attacks and Defenses for LLM Agents](https://arxiv.org/abs/2406.13352), Debenedetti et al. 2024, SOURCED abstract).
- **Settings writes bypass edit_guard.** A ConfigChange hook fires when a project, local or user settings file or a skill changes during a session, and exit 2 or `{"decision": "block"}` means the new settings "are not applied to the running session". A blocked change shows no message to anyone ([Hooks reference](https://code.claude.com/docs/en/hooks), SOURCED). edit_guard sees only Edit, Write and NotebookEdit, so a Bash redirect into `.claude/settings.local.json` is the open path in #191 (BELIEVED; not probed live). Posted on #191.
- **Sandbox scope, for #509 (SOURCED, [Configure the sandboxed Bash tool](https://code.claude.com/docs/en/sandboxing)).** The sandbox covers Bash, PowerShell and Monitor commands and their children only. File and web tools, hooks, MCP servers and mods run outside it. Network goes through a proxy whose allowlist starts empty. Reads default to "most of the machine, including credential files", so `sandbox.credentials` deny entries are needed. In a linked worktree, writes to the shared `.git` are allowed except `hooks/` and `config`. `.claude` settings, skills, agents and hooks are write-protected even under `allowWrite`. Anthropic measured "sandboxing safely reduces permission prompts by 84%" internally ([Making Claude Code safer with sandboxing](https://www.anthropic.com/engineering/claude-code-sandboxing), Anthropic 2025, SOURCED; vendor figure).

## 5. Claude Code features since v2.1.300 that bear on the harness
From the [Claude Code changelog](https://code.claude.com/docs/en/changelog) (SOURCED; [changelog_scan.py](_scratch/gap-survey/scripts/changelog_scan.py)):
- **Adopt.** `engines["claude-code"]` in plugin.json (2.1.323): a plugin outside its range "is not installed, updated or loaded"; only v2.0.15-2.1.75 reject the key ([Plugin manifest reference](https://code.claude.com/docs/en/plugins-reference), SOURCED) → #530. The ConfigChange hook → #191. The OTel additions: cache writes split by lifetime (2.1.300), `agent_id` on events (2.1.310), `safety_event` for every stop or prompt (2.1.307), `host.name` (2.1.326) → #502.
- **Owner's choice, user scope only.** `permissions.denyInsteadOfPrompting` (2.1.319) keeps an unattended session working by denying instead of prompting; its scope is "User or managed" ([Settings files and precedence](https://code.claude.com/docs/en/settings), SOURCED), so the template cannot set it. It serves #96. `permissions.blockWritesOutsideWorkingDirectories` (2.1.314) refuses Write, Edit and NotebookEdit outside the working directories in every mode ([Choose a permission mode](https://code.claude.com/docs/en/permission-modes), SOURCED).
- **Measure before adopting.** `CLAUDE_CODE_DISABLE_AGENT_PROGRESS_SUMMARIES` (2.1.323) turns off subagent progress summaries and "the requests that write them". The ceiling is small: Haiku side calls were 0.4 % of repo-E's spend (harness-efficiency.md §2), assuming the summaries are among them (ASSUMED).
- **Not now.** Cloud scheduled tasks can run on a self-hosted environment with GitHub triggers ([Automate work with scheduled tasks](https://code.claude.com/docs/en/routines), SOURCED), which could host #499's loop off the owner's laptop. The self-hosted environment pages and their plan requirements were not read.

## 6. What is not a gap (evidence against)
- **Researcher or builder auto-compaction.** Simulated on repo-E's runs at 150-200k, it saves 1-4 %; "runs are too short for compaction to pay" ([r2-research-and-lead-cost.md](_scratch/harness-efficiency/r2-research-and-lead-cost.md), VERIFIED there). The lead was the case that paid (#258, shipped).
- **A per-issue spend cap.** 4 of 46 issues (9 %) exceed 3x the median and hold 35 % of issue-attributed spend, the largest $12.51 (#464, the merge train, over 4 runs) (VERIFIED, [cost_tail.py](_scratch/gap-survey/scripts/cost_tail.py)). These were the hard issues, so a cap would cut work, not waste (BELIEVED); `maxTurns` already stops runaway loops.
- **Agent teams.** Teams "use about 7x more tokens than standard sessions" when teammates run in plan mode ([Manage costs effectively](https://code.claude.com/docs/en/costs), SOURCED via the #254 round file). This works against the owner's goal.
- **A condenser of our own.** OpenHands' 2x per-turn saving is a vendor claim for its own loop; Claude Code's compaction plays the same role here (BELIEVED).
- **SessionStart size.** `dev orient` prints 3,821 characters, under the 10,000-character hook cap (VERIFIED, 2026-11-19).
- **Model and effort routing.** These are already pinned per agent, with experiments filed (#262, #269).

## 7. Recommendation for this project: gaps ranked by expected effect per token
Ranks are BELIEVED and combine the token cost of the change with the size of what it moves (§3). Zero-token changes go first when their downside is unbounded.

| # | gap | token cost | expected effect | issue |
|---|---|---|---|---|
| 1 | Deterministic lead iteration | negative: removes lead turns | lead is 24 % of spend here and 16 % in repo-E; bookkeeping is 31.9 % of lead turns | #499 |
| 2 | Refuse GitHub write actions outside a worker's role | zero | closes the blast radius of any injected or overeager instruction (capability scoping: 3/75 vs 33-47/75) | **#528** (new) |
| 3 | Claude Code version floor plus doctor check | zero | the fail-closed guards (`onFailure: block`, v2.1.295+) cannot silently fail open on an old client | **#530** (new) |
| 4 | Measure: OTel plus PR data per merged issue | none at runtime | every other rank becomes a measurement; exact output cost; joins machines | #502 |
| 5 | Symbol-level wave planning | small (refs lookups) | fewer collision send-backs, the main 2026-11 rework | #507 |
| 6 | Required review on harness code, tester after merge | reviewer runs at 4 % of spend | blocking defects found on nearly every feature PR | #501 |
| 7 | ConfigChange guard for settings env | zero | closes the Bash path around edit_guard | #191 (comment) |
| 8 | Sandbox for workers plus an injection red-team set | zero runtime; setup friction | blocks network exfiltration and settings writes from Bash; 84 % fewer prompts (vendor) | #509 |
| 9 | Acceptance tests before the builder | +tester run per issue | "met" becomes checkable; fewer review rounds (unmeasured) | #503 |
| 10 | Eval pass rate as a release condition | one eval run per release | stops surface regressions the gate cannot see | #506 (with #97, #4) |
| 11 | Spotlighting in `brief` | about 1 % more brief text | a weak layer alone (adaptive attacks >50 %); cheap after #528 | #56 |
| 12 | Memory notes re-verified against transcripts | an occasional pass | gotcha lines that drift stop misleading every session | #297, #299 |
| 13 | Per-host Owns and HANDOFF; fleet view | small | multi-machine conflicts and stale pins | #79, #80, #505 |
| 14 | Owner dashboard | none for agents | owner status questions answered without a model turn | #508 |

Bounds: the dollar shares are one machine's 30 days (5 lead sessions, 89 subagent runs) and repo-E's 6 days, with output modelled, not billed. Re-rank with #502's data once it has 30 merged issues.
